# יועץ הרכב של שטראוס

צ'אטבוט בעברית שעונה לעובדים על השאלה: **מה יקרה לשכר הנטו שלי אם אחליף רכב חברה, אעבור לרכב חשמלי או אוותר על הרכב?**
הבוט אוסף את הנתונים בשיחה, בודק זכאות לפי מדיניות החברה, ומחשב את הנטו היום מול הנטו בחלופה.

## עיקרון מרכזי

**החישוב נעשה בקוד דטרמיניסטי, לא במודל השפה.** המודל מנהל את השיחה ומפעיל כלים; הוא אינו מחשב ואינו מנחש מספרים.
כל סכום שמוצג לעובד חייב להגיע מהעובד או מתוצאת כלי, ויש שומר בקוד שמזהה סכום שלא הגיע מהם ומחליף את התשובה.

**האתר החי:** https://strauss-car-advisor.onrender.com (שירות חינמי: ייתכנו כדקה של המתנה בכניסה ראשונה אחרי שינה; הכניסה עם שם משתמש וסיסמה).

## מה במערכת

- **התחברות:** שם משתמש וסיסמה לעובדים ולנציגים. עובד רואה רק את מסך העובד ואת השיחות שלו, נציג רק את מסך הנציג. בסרגל הצד של העובד: "שיחה חדשה" והיסטוריית השיחות (פתיחה, שינוי שם ומחיקה עם אישור, כמו בצ'אט מוכר), ובתחתיתו איקון הגדרות (האזור האישי: החלפת שם משתמש וסיסמה, שני הכפתורים סגורים עד לחיצה, נדרשת הסיסמה הנוכחית) ואיקון יציאה. בבאנר אין כפתורי ניווט.
- **מסך עובד:** שיחה עם הבוט על כל המסך, בורר רכבים, ובצד (לפי מתגים בשיחה): כרטיס "הנתונים שנקלטו עד כה" שמתמלא בזמן אמת, והשוואה מפורטת (טבלה, הסבר, העתקה והורדה).
- **מסך נציג תחבורה:** שאלות שהבוט שלח כשחסר נתון שהעובד לא יודע (למשל השתתפות ברכב החדש). התשובה חוזרת לשיחה והחישוב ממשיך מאותה נקודה, על הרכב שעליו נשאלה השאלה.
- **סוכן עם 8 כלים** (עדכון נתונים, חיפוש רכב, בדיקת זכאות ותקציב, שווי שימוש, חישוב נטו, פנייה לנציג ועוד). תיאורי הכלים נמצאים בקובץ נפרד: `backend/tool_specs.json`.
- **אכיפת מדיניות בקוד:** קבוצת זכאות (עיסוק קובע קבוצה), מסלול ברוכת ילדים (לפחות 4 ילדים עד גיל 23), תקציב, ויתור לפי טבלת העיסוקים, ללא פדיון תקציב שלא נוצל.

## מבנה הפרויקט

```
data/        קבצי הנתונים של האתגר (שווי שימוש 2026, אקסל, rules_config.json) והקבצים שנוצרו מהם
backend/
  usage_value_db.py    מאגר שווי השימוש של רשות המסים (מפתח רשמי: שנת מס + שנת רישום + סוג + תוצר + דגם)
  data_store.py        טעינת הקטלוג, העיסוקים והחוקים (עם בדיקת תקינות)
  rules_validation.py  בדיקה שקובץ ההגדרות תקין ושכל הערכים בו נתמכים
  calc_engine.py       מנוע החישוב (מס הכנסה, ביטוח לאומי, פנסיה, קרן השתלמות, החזר חשמל)
  eligibility.py       כללי זכאות ותקציב
  state.py / db.py     מצב השיחה ו-SQLite (שיחות, שאלות לנציג)
  agent_tools.py       הכלים של הסוכן
  agent_tools_registry.py  חיבור הכלים לתיאורים ב-tool_specs.json
  agent.py             לולאת הסוכן, מודלי גיבוי, שומר המספרים
  actions.py           פעולות מסך שאינן עוברות דרך המודל
  prompts/system_prompt.md  הנחיות המערכת
frontend/    Streamlit: app.py, ui.py, views/employee.py, views/representative.py
scripts/     convert_excel.py, eval_agent.py, chat_cli.py
images/      תמונת הבוט
```

## הגדרות (קובץ `.env`)

העתיקו את `.env.example` ל-`.env` ומלאו מפתח:

```
LLM_PROVIDER=gemini
LLM_MODEL=gemini-3.1-flash-lite
LLM_FALLBACK_MODELS=gemini-3.5-flash-lite,gemini-3.5-flash
GOOGLE_API_KEY=המפתח-שלכם
GOOGLE_API_KEY_2=            # אופציונלי: מפתח גיבוי
AUTH_USERS=dana:סיסמה-ארוכה:employee:דנה כהן;moshe:סיסמה-אחרת:rep:משה לוי
```

- **משתמשים:** כל רשומה היא `שם_משתמש:סיסמה:תפקיד:שם_תצוגה` (תפקיד: `employee` או `rep`), מופרדות ב-`;`. אסור להשתמש ב-`:` וב-`;` בתוך שם או סיסמה, והסיסמה באורך 6 תווים לפחות. המשתמשים נטענים למסד בעליית השרת. משתמש שכבר קיים לא נדרס, כך שהחלפת סיסמה או שם משתמש באזור האישי נשמרת כל עוד המסד נשמר (וגם שם שהוחלף לא נוצר מחדש). האות הראשונה של שם התצוגה מופיעה בעיגול ההודעות של העובד.
- **מילוי מראש לדמו (אופציונלי):** `LOGIN_PREFILL_USER=dana` ממלא במסך הכניסה את שם המשתמש והסיסמה של העובד הזה (לפי `AUTH_USERS`), כך שמספיק ללחוץ "כניסה". הסיסמה נשלחת לדפדפן, ולכן **כל מי שפותח את האתר יכול להיכנס כמשתמש הזה**. זה חל על עובד בלבד, ולא על נציג. מומלץ להסיר את ההגדרה אחרי הדמו.
- בלי `AUTH_USERS` אי אפשר להיכנס. לפיתוח מקומי בלבד אפשר להגדיר `AUTH_DISABLED=1`, שמבטל את ההתחברות ומציג את כל המסכים. **לעולם לא להגדיר אותו בענן.**

- **מפתח גיבוי:** מכסת Gemini נספרת לכל פרויקט Google, ולכן מפתח גיבוי צריך להיות מפרויקט נפרד. כשהמכסה של המפתח הראשון נגמרת, המערכת עוברת למפתח השני באותו מודל, ורק אחר כך למודל הבא.
- אפשר גם להפעיל חיוב (Billing) על הפרויקט, ואז המכסה גבוהה בהרבה.
- הקובץ `.env` אינו נכנס ל-git. אל תשתפו אותו.

## הרצה

```bash
streamlit run frontend/app.py
```

האתר נפתח בכתובת http://localhost:8501. מזהה השיחה נשמר בכתובת (`?sid=...`), ולכן רענון ממשיך את אותה שיחה. מסך הנציג נמצא בכפתור "מסך נציג" בבאנר.

## הרצה עם Docker

```bash
docker compose up --build
```

האתר ב-http://localhost:8501. המפתחות נקראים מקובץ `.env` בזמן ההרצה (לא נארזים בתוך התמונה), ומסד הנתונים נשמר ב-volume בשם `advisor-data`, כך שהשיחות שורדות הפעלה מחדש. הערה: ה-Docker לא נבדק על המחשב שבו פותח הפרויקט (לא מותקן שם).

## פריסה לענן

הקונטיינר מקשיב לפורט שהפלטפורמה מעבירה במשתנה `PORT`, ומסד הנתונים נשמר בנתיב `STRAUSS_DB_PATH` (ברירת מחדל בקונטיינר: `/data/advisor.db`). לכן צריך דיסק קבוע שמחובר ל-`/data`. הקובץ `render.yaml` הוא דוגמת פריסה חינמית ל-Render (לא נבדק מול Render בפועל, ויש לאמת מול התיעוד שלהם). בתוכנית החינמית אין דיסק קבוע, ולכן מסד הנתונים נשמר ב-`/tmp` והשיחות והשאלות לנציג נמחקות כשהשירות נרדם או מופעל מחדש; השירות גם נרדם אחרי זמן ללא פעילות, והפעלה ראשונה אחריו איטית. לשירות עם נתונים קבועים יש לעבור לתוכנית בתשלום ולהוסיף `disk` עם `mountPath: /data` ו-`STRAUSS_DB_PATH=/data/advisor.db`.

משתני סביבה להגדיר בפלטפורמה (לא בקוד ולא ב-git):

| משתנה | תפקיד |
|---|---|
| `GOOGLE_API_KEY` | מפתח Gemini ראשי |
| `GOOGLE_API_KEY_2` | מפתח גיבוי מפרויקט Google נפרד (אופציונלי) |
| `AUTH_USERS` | **חובה.** המשתמשים: `שם:סיסמה:תפקיד:שם תצוגה` מופרדים ב-`;`. בלי זה אי אפשר להיכנס |
| `STRAUSS_DB_PATH` | מיקום מסד הנתונים, על הדיסק הקבוע |

מגבלה: השירות חייב לרוץ כמופע אחד בלבד (SQLite ומצב השיחה אינם מתאימים לכמה מופעים במקביל).

### שעון מעורר (שירות חינמי שלא נרדם)

הקובץ `.github/workflows/keep-alive.yml` שולח פנייה לאתר כל כ-10 דקות, כדי שהשירות החינמי ב-Render לא יירדם. הגדרה חד-פעמית ב-GitHub: Settings → Secrets and variables → Actions → Variables → New repository variable, בשם `APP_URL` ועם כתובת האתר ב-Render. אפשר להפעיל גם ידנית מלשונית Actions. חלופה בלי GitHub: שירות ניטור חינמי כמו UptimeRobot, שפונה לכתובת `‏<כתובת האתר>/_stcore/health` כל 5 דקות. הפנייה מונעת שינה אבל לא שומרת נתונים: שיחות עדיין נמחקות כשהשירות מופעל מחדש (למשל בפריסה חדשה).

## קובץ ההגדרות והנתונים

כללי המדיניות נמצאים ב-`data/rules_config.json` והם מקור האמת של החישוב והזכאות. הקוד בודק את הקובץ בעת הטעינה ומסרב לערכים שאינו תומך בהם, עם הודעה ברורה. נתוני הקטלוג והעיסוקים נוצרים מהאקסל של האתגר באמצעות `scripts/convert_excel.py`.

## מגבלות ידועות

- התלות במודל שפה חיצוני (Gemini): חלק מהכללים בניסוח ובסדר השיחה אינם נאכפים בקוד. מפתח חינמי חשוף לשגיאות מכסה ועומס.
- ההשוואה היא הערכה לפי כללי הקובץ ולוחות המס, ואינה תחליף לתלוש השכר.
- משתמשים מוגדרים מראש במשתנה סביבה; אין עדיין מסך ניהול להוספה והסרה של משתמשים. בשירות החינמי (בלי דיסק) הסיסמאות ששונו והיסטוריית השיחות נמחקות כשהשירות מופעל מחדש.
- נתוני העובד מוקלדים בשיחה ואינם נמשכים ממערכת שכר.
